## 2. Chosen stack and why

| Choice | Why |
|---|---|
| Plain JavaScript ES modules, no framework | This is the simplest option that fits the spec. The same `src/engine/*` modules run unchanged in Node (tests, simulation) and in the browser. TypeScript was skipped to avoid a compile step for Node, since the spec only *suggests* it. |
| Layered inline **SVG** on a 1920×1080 stage, scaled uniformly and letterboxed | The approved art is SVG generated by `_render/*.py`. Porting those primitives to JS (`src/ui/svg.js`) reproduces the mockups at the same coordinates, gradients and tokens, and stays crisp at any scale. |

| **node:test** | Built into Node 20, so no extra test dependency is needed for E1/E2. |
| **puppeteer-core** + installed `/usr/bin/google-chrome` (v155) | Runs headless UI tests and screenshots without downloading a browser. Playwright would also work, but puppeteer-core can use the system Chrome directly. |
| `@fontsource` Lobster / Carter One / Nunito (OFL 1.1) | Fonts are bundled locally as WOFF2. No CDN is used at runtime. |
| Procedural Web Audio | No audio files existed, and the spec allows procedural audio. All sounds are original (see `AUDIO.md`). |

## 3. Completed features

- **Logic core** (`src/engine/`), framework-free: config with the locked paytable and layout, plus a startup assertion
  against `design-tokens.json → board-arrangement` (counts 21/19/7/2/1, total weight 2,093). RNG uses
  `crypto.getRandomValues` with rejection-sampled `randInt`. A seeded sfc32 RNG exists for tests and simulation only.
  `weightedPick`, `drawRound` (s1 → DR = randInt(25)==0 → s2 drawn with s1's weight excluded) and integer `payout`.
  Gamble uses randInt(2), is capped at 3 flips, and is disabled when 2×win > 30,000 (it never truncates a win).
  Bet operations clamp to square/round/balance limits and show the exact toast texts. Undo stack, Clear, and Rebet
  with an affordability tooltip are included.
- **State machine**: `INIT → (RECOVERY) → BETTING → SPINNING → RESOLVING → [DOUBLE_RUN] → (GAMBLE_OFFER ⇄ GAMBLE) →
  PAYOUT → BETTING`, plus `ERROR` from any state. Every command goes through one `dispatch(action)` with a static
  acceptance table and guards. Each round has a unique `roundId` and is settled at most once. Balance changes only
  at START, PAYOUT and Refill.
- **Persistence and recovery**: keys `rl.v1.balance|settings|lastBets|round|history`. **Atomic write approach:** the
  round record carries the resulting balance plus a monotonically increasing `seq`, and is written first in one
  `setItem`. `rl.v1.balance` stores `{v, seq}`. On load, whichever record has the higher `seq` is authoritative, so a
  crash between the two writes can never desync balance and round. A gamble result is written before its reveal.
  PAYOUT writes `phase=PAYOUT` first, then `settled=true` together with the new balance. On reload with an unsettled
  round: Recovery modal → Continue shows the stored stops directly and resumes at the stored phase (offer, pending
  reveal, or credit). Nothing is ever redrawn. All storage values are validated (types, ranges, known squares,
  consistent totals and wins). A corrupt key goes to ERROR, and Reload resets **only** that key. An unreadable
  balance falls back to the round record's balance or 1,000, and is logged. If localStorage is unavailable, the game
  runs in memory and shows a "Progress won't be saved" toast.
- **UI** matching mockups 01–09b and both component sheets: top bar, board, centre panel (marquee sign, state text,
  Double Run lamp, mini paytable, last result), right panel (cards, limits, chips, Undo/Clear/Rebet, START or
  Collect + Gamble ×2, 10-round history with ONE double-width Double Run entry, message slot with toasts), footer key
  hints, and modals (gamble flip, refill, error, recovery, tabbed Settings/Paytable/Help with the RTP ≈ 95.45% badge,
  the disclaimer, and Turbo shown disabled as "PLACEHOLDER – pending approval" with no function). Also: loading
  screen, "Please enlarge window" below 1280×720, money values redrawn above modal scrims, and all square states
  (idle, hover + 300 ms tooltip, focus, bet, ghost, lit, trail1/2, winner, second/winner2, dimmed, locked with
  padlock).
- **Animations**: outcome-first light path, 4.0–5.6 s with a fixed accelerate/cruise/decelerate shape and a 2-bulb
  trail. A runtime integrity assertion checks that the final animated index equals the stored stop; a mismatch goes
  to ERROR. Double Run: banner 0.6/0.4/0.3 s plus a bunting flash, then a 2–3 s turquoise second light starting after
  s1. Wins: small pulse; big marquee chase plus ≤40 confetti/bulb sparks clipped to the board; a 1920x jackpot
  ribbon ≤4 s, skippable with click/Space/Esc. Count-ups ≤1.5 s (click to fast-forward). Gamble: 140 ms pick, 1.2 s
  alternation that slows over the last 300 ms, then a 300 ms settle on the stored colour. Loss is a soft fade.
  Reduced motion: 3-step 0.8 s fade, no chase/particles/marquee, instant count-ups, gamble reveal after 0.6 s with
  text. It defaults to `prefers-reduced-motion`.
- **Keyboard and accessibility**: full B8 key map, including R/W/←/→ scoped to the gamble modal, G, Enter = Collect,
  and **Space activating the focused control** (B13 fix 2). `event.repeat` is ignored for all action keys. Tab order
  is top bar → squares (roving tabindex, arrows follow the track) → chips → Undo/Clear/Rebet → START. The gamble
  modal order is RED → WHITE → GAMBLE → COLLECT. Focus is trapped in modals via `inert`, and initial focus goes to
  the safest action. White-on-night focus rings follow the tokens. aria-live (polite) covers state text, toasts and
  balance changes. Each square's accessible name reads "Square 12, pays 96x, your bet 5".
- **B13 fix 1**: "★ WIN" / "WIN 2" tags are inset inside the square's top-left (44×16 px), clear of the bet badge, so
  they never clip the frame or overlap neighbours on any edge. Verified on #13 and #8 in both Double Run orders.
- **Audio**: procedural BGM `bgm_perya_loop` (+ `amb_crowd_bed`) and every SFX ID from animation notes §3. Muted until
  first interaction. Master mute (M + icon), Music/SFX volumes persisted, BGM ducks −6 dB.

## 6. Deviations from the spec

1. **Light laps**: about 0.5–1.5 laps instead of "2–4 laps", to keep both the token cruise speed (≈18 sq/s, which
   actually ranges 7–30 sq/s for exact landing) and the 4–6 s duration. See Q1.
2. JavaScript instead of TypeScript, and puppeteer-core instead of Playwright. Both were suggestions, not
   requirements.
3. The simulation's long run skips JSON serialization (§4). It was cross-checked with a 1M run per strategy using
   real serialization.
4. Audio is procedural rather than OGG/AAC files (allowed). LUFS targets were not measured.
5. The Double Run banner animates in and out before the second light (animation notes), then is shown statically on
   the result state, as mockup 04 shows it there.

## 7. Remaining defects and limitations

- E5 "tab hidden mid-spin" is tested by suspending the rAF animation loop, which is the same mechanism browsers use
  for hidden tabs. A real tab switch was not tested, because headless Chrome does not change visibility.
- E3 tests run with a cosmetic animation speed-up (`timeScale` 4) in test mode for speed. The reduced-motion, START
  and recovery tests ran at real speed.
- Firefox, Edge and Safari were **not tested**. Only Chrome 155 was available on the box. `inert` and
  `transform-box` need current browsers.
- 60 fps and the "no memory growth over 1,000 rounds" requirement were not measured with a profiler. The design
  supports both: only the small light layer re-renders per step, history is capped at 50 stored and 10 shown, and
  confetti is capped at 40.
- ★ ← → ≈ ✓ ▸ are not in the bundled Latin font subsets and render from a system fallback font. On a machine with no
  such fallback, they could show as boxes.
- `public/fonts/` still contains unused duplicate `.woff2` copies, which are also copied to `dist/fonts/`. The
  bundled fonts in `dist/assets/` are the ones actually used. Deleting the duplicates needed a file-removal approval
  that was not given in this session.
- Client-side only: credits can be edited in devtools (accepted in spec F). Test mode can likewise be enabled by
  defining `window.__RL_TEST__` before load. It is not reachable from the UI.

## 8. Open questions / blockers (no blockers)

- **Q1** Light path: the spec says "2–4 laps" but also cruise ≈18 sq/s and 4–6 s total, and these conflict. At
  18 sq/s, 4–6 s is about 1–1.5 laps. Two laps or more would need about 25–64 sq/s. Implemented: tokens kept,
  0.5–1.5 laps. Which should win?
- **Q2** WIN tag placement (B13 fix 1): inset at the top-left (44×16 px). It slightly overlaps the top of the bulb
  socket. Is this acceptable, or is another placement preferred?
- **Q3** Copy for states without a mockup was kept minimal: mid Double Run "Double Run… / Second light running · it
  never stops on #N", PAYOUT "You win N / Added to your credits", gamble loss "No win this time". It needs approval.
- **Q4** Ghost badges hide as soon as any live bet is placed. The spec does not say.
- **Q5** A corrupt *settings* key also goes to ERROR, following the spec literally. Should it silently reset to
  defaults instead?
- **Q6** Info/Settings icons are also disabled in GAMBLE_OFFER, GAMBLE, PAYOUT, RECOVERY and ERROR, as the mockups
  show. The spec text lists only the run states.
- **Q7** Is procedural audio acceptable as the final audio, or should produced OGG/AAC files replace it later?
