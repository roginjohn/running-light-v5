# v3 Batch 5: result states

Branch `v3/batch-5-results`. Not committed. This batch restyles the win, gamble offer, gamble flip (win and lose), loss and Double Run result states to the flat v3 look of `win-gamble-offer.png`, `gamble-flip.png`, `loss.png`, `double-run-result.png` and the component sheet. The big mono number stays the **multiplier** (confirmed by Rogin). Overlays (settings / paytable / help, refill, error, recovery), small-screen layouts (batch 6) and the credits count-up (batch 7) are not touched. There are still no Manual/Auto tabs, and the Start button wording is unchanged. Nothing under `src/engine/` was touched (`git diff main -- src/engine` is empty). The gamble is still 50/50, max 3, 30,000 cap, all from the engine.

**No long tasks over 50 ms** in any segment, with or without throttling. The light run is unchanged from batch 4 (0 forced layouts, ~1.1 small contained layouts per step). The first trace of the new flow found one 61.8 ms task and **121 forced layouts** in the win reveal at 4×: the rail-note count-up rebuilt the rail every frame and the focus restore on the rebuilt Collect button forced a layout each time. With `paintWin` (text only) that is **1** forced layout per segment (the one focus move when the state changes). The longest remaining tasks are the one-off full renders when a result appears (44.7 ms at 4×). The flip itself is a compositor `transform` animation; the centre is rebuilt at most 4 times for one flip (UI test).

## Differences from the mockups
- **No Manual/Auto tabs**, and the primary button still says **Start · 20 credits on 6 squares · Space** (open questions 6–7, unchanged as asked). The loss sub line therefore says "Press **Start**", not "Place bet".
- **Loss rail** keeps the batch-3 note "Last win 0 · no win this round" (the mockup has no note there).
- **Gamble picking state** (not mocked): the middle shows "or" until a flip; the Gamble button reads "Pick red or white · R / W, then G" before a pick. After a flip the disc rests on the last result.
- **The flip** is a real 3D `rotateY`; the mockup's static "mid-flip" frame is a `scaleX`. The screenshot freezes the disc at 72°.
- **Big number "+ 24.00x"**: the `.big` box keeps its fixed 8.2ch width (strict containment from batch 4), so the gap before "+" is set by right-aligning the number in that box; slightly wider than the mockup at 1920.
- **"1st" / "2nd" on 48 / 39 / 38 px tiles** (1280, 1024, 768): 10 px with the badge moved 2–4 px outwards so they do not overlap; on the 38 px tablet tile they sit edge to edge.
- **Jackpot (1920x)**: no mockup (open question 15). It now uses the same flat win state (Jackpot pill, 1920.00x) instead of the v2 confetti overlay. Please confirm.
- Compare images at 1280×720 and 768×1024 use the 1920×1080 mockup, letterboxed; there are no result mockups at those sizes.
